## The 10 major improvements

### Applied directly (verified, >99% safe)

**1. Fixed the bug that broke most of the Prior Strength tab** — `R/prior_strength.R`

*What it does:* `prior_strength_weights()` and `prior_strength_thresholds()`
validate that scale-like parameters are positive. The spec's
`positive_params` list mixes prior-side and likelihood-side names (e.g.
`c("sigma0", "sigma")` for the Normal case), but the code checked **both**
parameter sets against the **whole** list. The prior list has no `sigma`, the
likelihood list has no `sigma0` — so validation failed on every single call,
for every likelihood family.

*Blast radius (reproduced by running the code):* the Summary table errored
for all three likelihood families, including the tab's default state, and the
"Prior share vs n" plot errored for Bernoulli and Poisson. Only the
Normal-mean plots worked, because they compute their math inline instead of
calling these functions.

*The fix:* validate each parameter set only against the positive-parameter
names it actually owns:
`intersect(spec$positive_params, spec$prior_params)` for the prior and
`intersect(spec$positive_params, spec$likelihood_params)` for the likelihood.
Genuinely bad input (negative sigma, zero alpha, n ≤ 0) is still rejected —
the tests prove both directions.

*Why this can't break anything:* the previous behavior was an unconditional
error. Every code path that changes was already crashing.

**2. Added a test suite: `tests/test_core.R` (64 checks, all passing)**

The repo had no tests, which is what let improvement #1's bug ship silently.
The suite covers all 15 distribution samplers (counts, positivity, bounds),
`resolve_params`, HDI/summary math, simulation output shapes for all six
model families, template/preset integrity (every default and preset
distribution must exist and be allowed), the full prior-strength arithmetic
(including regression tests for bug #1), and a `parse()` check on every R
file. It needs **only base R** — no packages — so it runs anywhere:
`Rscript tests/test_core.R` (exits non-zero on failure).

**3. Added CI: `.github/workflows/tests.yml`**

Runs the test suite on every push and pull request via `r-lib/actions/setup-r`.
Because the tests are dependency-free, the workflow is two steps and fast.
This cannot affect the app itself; worst case is a red check. Watch the first
run on this PR to confirm it's green.

**4. Added `README.md`**

The repo had no documentation at all. The README covers what the app does

architecture, how to run the tests, and the honest caveats already in the UI

**5. Unified the plot theme and fixed the light/dark clash** — `R/plots.R`,

**9. Deduplicate the Normal-mean posterior/KL math** — `R/prior_strength_tab.R`

The precision-weighting and KL formulas are written **twice** — once in
`strength_grid` (drives the plots) and once in `summary_table`. If you ever
adjust one (e.g., the `Sxx` refinement your note mentions), the other will
silently disagree. Both formulas are vectorized already, so the fix is to add
one helper to `R/prior_strength.R`:

```r
normal_mean_metrics <- function(mu0, tau0, beta_hat, sigma, n) {
  w_prior <- 1 / (tau0^2)
  w_like <- n / (sigma^2)
  s2 <- (sigma^2) / n
  list(
    prior_share = w_prior / (w_prior + w_like),
    posterior_mean = (w_prior * mu0 + w_like * beta_hat) / (w_prior + w_like),
    kl = 0.5 * (log(s2 / (tau0^2)) + (tau0^2 + (mu0 - beta_hat)^2) / s2 - 1)
  )
}
```

and call it from both places (grid: `n = n_values`; summary: `n = n_ref`).
Not applied because it rewrites working numeric code — behavior-preserving,
but it deserves your eyes since these formulas feed the academic write-up in
`experimental/`.

### Escalation (Tier 3 — your decision)

**10. The rstanarm preset is a visible dead end**

**Plain terms:** The preset dropdown on every model tab offers
"rstanarm (placeholder)". Choosing it does nothing except show "not wired
yet." Anyone you share the app with will try it, and it makes the polished
brms preset look less trustworthy by association. Do nothing, and every
session includes one advertised feature that doesn't work.

**Technical terms:** `build_rstanarm_defaults()` in `R/priors_registry.R`
just returns the custom defaults. Wiring it properly is not mechanical:
rstanarm's defaults are **autoscaled** — e.g. `stan_glm` uses
`normal(0, 2.5 * sd(y)/sd(x))` for coefficients — so they depend on data the
app doesn't have. You'd need to either present the unscaled base values
(`normal(0, 2.5)`, intercept `normal(0, 2.5)` after centering, exponential(1)
rescaled) with a caveat, or add a "assumed data scale" input.

**Options:**
- **A. Hide the option until wired** — delete the choice from the dropdown
  (2-line change in `R/modules.R`, preset infrastructure stays). *My
  recommendation: honest UI now, zero statistical risk, easy to restore.*
- **B. Wire the unscaled rstanarm base defaults** with an "assumes
  autoscaling with unit-SD data" note — more useful, but the caveat is doing
  a lot of work and could mislead.
- **C. Leave as is** — the "(placeholder)" label is at least truthful.
